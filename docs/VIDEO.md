# ghoulballs video edition

The video edition is separate from the live GIF collection. Its selected format
is lossless BI_RLE8 AVI: 512×512, 50 frames at 25fps, exactly two seconds, no audio.
The logical artwork remains `GHOULBALLS_VAPOR_V3` at 64×64; larger pixels are exact
nearest-neighbour enlargement. Files, static SVG posters and the embedded decoder
are generated by one read-only contract call, without stored movies or external
playback assets. No GIF is included in the new metadata.

The edition is deployed on Base as
[`0x318761bb4cac5fb8eea16fe7af3176f4915a83f9`](https://basescan.org/address/0x318761bb4cac5fb8eea16fe7af3176f4915a83f9),
with renderer `0x25ff2902374541f04a4e74ce1c3cbd418aca8d94`.
The constructor/deployment first mint belongs to the deployer. Both the one-token
canary and actual edition [token 1](https://opensea.io/item/base/0x318761bb4cac5fb8eea16fe7af3176f4915a83f9/1)
pass OpenSea playback: the iframe animates and its rehosted HTML is byte-identical
to the onchain player. All 50 frames of each deployed token also match the independent
RGB reference. Live receipts, bytecode hashes and media evidence are committed.

## Implementation and validation

`AviRleVideo` exposes `aviFromSeed(size, seed)` (256/512), `posterFromSeed(seed)`
and the same recipe/trait ABI as the existing renderer. RLE8 emits complete,
independent bottom-up frames with `00dc` chunks and a complete RIFF index. It
rasterizes each logical frame once and copies compressed rows vertically. The
original uncompressed AVI, MPEG and GIF encoders are unchanged.

`VideoNFT` exposes `mint`, `mintTo`, `seedOf`, `recipeOf`, `video`, `imageURI`,
`animationURI`, `tokenURI`, format and dimension getters. It has no owner, upgrade,
metadata setter or protocol fee: 6,667 tokens maximum, one mint per caller.
`VideoCandidate` uses the same renderer/metadata but mints exactly one token to its
deployer in its constructor; all subsequent mint calls revert. Its collection name
identifies it as a compatibility candidate. Its inherited edition `MAX_SUPPLY`
getter remains 6,667; the stricter `CANDIDATE_SUPPLY = 1` is enforced for the canary.

Actual 500M-capped STATICCALLs cover all **64** combinations of ball count, theme
and motion. All **3,200 frames** match the independent Python RGB reference and
FFmpeg; the embedded JS decoder matches FFmpeg RGBA on every frame. Static posters
also match frame zero. Full metadata is approximately **231–311M gas**, including
poster, player, base64 layers and ABI return copying; maximum URI size is about
**1.17MB**. These measurements are sampled coverage, not a mathematical worst-case
proof over all seeds. Exact profile measurements live in `previews/video/validation-*.json`.

Chrome and Firefox have passed real loop, pause and resume tests. Chrome also
passes the separate mint page with a mocked wallet, original AVI download, gallery,
RPC failure handling and mobile layout. Safari remains untested; it needs macOS.
Browser QA never sends real transactions. Screenshot files showing an open mint
are **mocked QA**, not a live deployment or an OpenSea compatibility claim.

## Release gates

The diagnostic probe is on Base; its independent deployment manifest and public
OpenSea observations are in `deployments/marketplace-probe-base.json` and
`previews/probe/opensea/`. API authentication errors are recorded separately and
are not interpreted as media incompatibility. Marketplace caching/rehosting is
allowed; the original token media requires no project-operated hosting.

1. Confirm inline HTML and payload/gas controls on OpenSea; keep the observed
   encoding as the AVI candidate. Do not build MPEG P-pictures or H.264 unless the
   actual AVI candidate fails the applicable gates.
2. After explicit broadcast authorization, deploy `DeployVideoCandidateBase` and
   its renderer with the encrypted `ghoulballs_base` signer. The script measures
   complete token 1 metadata after minting in its dry run. Do not reuse the Sepolia key.
3. Record confirmed candidate receipts and compare runtime bytecode (including
   the renderer immutable) against the Base build. Inspect the actual candidate on
   OpenSea, save screenshots and moving-media evidence, then record its URL/time
   under `candidate.opensea_playback`. A probe control does not satisfy this gate.
4. After edition broadcast authorization and candidate success, deploy
   `DeployVideoBase` (renderer, collection, first mint in one broadcast). Record its
   receipts independently and confirm the actual edition token on OpenSea too.
5. Only then record top-level `opensea_playback.status = passed` with its production
   token URL/time. `sync_video_config.py` requires that URL to identify this edition
   before it enables minting. Keep `/video/` disabled until then. Source verification
   uses Solidity 0.8.30, Cancun, via IR, optimizer 200; retain exact standard JSON
   inputs and constructor renderer address when verifying.
   `export_video_verification.py` reproduces exact creation/runtime bytecode from
   the committed Standard JSON inputs before any explorer submission.

wrong chain. Base uses the Cancun profile; Ethereum Sepolia uses Amsterdam. Never
copy a local simulation address into confirmed deployment fields. Keep hosted GIF
mint configuration and artwork unchanged when publishing the new video route.
